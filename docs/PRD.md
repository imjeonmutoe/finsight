# PRD: FinSight

## 목표
카드사·은행에서 받은 CSV 명세서를 올리면, 지출이 어디로 새는지를 5분 안에 알려준다.

## 사용자
가계부 앱에 매번 손으로 입력하다 포기한 개인. 카드 명세서는 매달 나오지만 열어보지 않는다.
한국 거주, 원화(KRW) 거래, 국내 은행·카드사 CSV를 사용한다. 계정당 1인 사용.

## 프로젝트 성격

**포트폴리오/데모다.** 실제 사용자의 카드 명세서를 모집하지 않고, 평가용 샘플 CSV를 제공한다. 결제는 Polar **샌드박스**를 쓴다.

다만 아래는 실제 코드로 만든다 — 데모의 목적이 "돌아가는 척"이 아니라 "프로덕션으로 승급 가능한 구조"이기 때문이다: 결제 웹훅 서명 검증과 구독 상태 동기화, RLS 전체, 삭제 정책, 프롬프트 인젝션 방어, 금융 데이터 로그 금지.

반대로 아래는 데모 범위에서 **의도적으로 만들지 않는다**: 개인정보처리방침의 법적 검토, 실 PG 심사, 사용량 과금 정산, 감사 로그, 계정 삭제 셀프서비스(문의 경로로 접수), LLM 호출량 쿼터 시스템(ADR-012).

## 핵심 기능
1. **CSV 업로드 & 자동 파싱** — 카드/계좌 별칭을 선택하고 파일을 업로드한다. 인코딩(EUC-KR/UTF-8)을 감지하고 첫 20행에서 원본 값을 제거한 컬럼 의미·형식 정보로 매핑을 추론한다. 사용자가 매핑·거래 유형·청구월을 확인한 뒤 저장한다. 불확실한 중복은 추가/중복 여부를 확인한다. 원본은 Supabase Storage에 보관하며 파일당 4MB·10,000행까지 지원한다.
2. **카테고리 자동 분류** — 고정 12개 카테고리. ① 사용자가 만든 가맹점 규칙 ② 내장 가맹점 사전 ③ 위 둘이 못 잡은 것만 Claude 순으로 분류한다. 사용자가 개별 거래를 고치면 "이 가맹점 → 이 카테고리" 규칙으로 저장돼 다음부터 자동 적용되고, 그만큼 모델 호출이 줄어든다.
3. **기간별 지출 추이** — 월별·카테고리별 지출 변화. (Pro)
4. **구독 누수 & 이상거래 탐지** — 정기결제로 판정된 항목 목록과 월 합계, 금액 인상 감지. 카테고리 중앙값 대비 이상치 거래. **탐지는 전부 코드로 계산한다.** (Pro)
5. **AI 월간 요약** — 이미 계산된 숫자를 근거로 Claude가 요약 문장을 작성한다. 모든 문장은 근거 거래로 링크된다. **Free도 받는다** (`claude-sonnet-5`). Pro는 같은 기능을 `claude-opus-5`로 받고, 입력에 기간별 추이·구독·이상거래가 더해져 절약 제안과 이상지출 해석까지 나온다. (ADR-015)

## 요금제

Pro는 **월 ₩9,900** 단일 월간 플랜이다(연간 플랜은 MVP 제외). 결제는 Polar 샌드박스를 쓴다.

| | Free | Pro |
|---|---|---|
| 업로드 · 원본 보관 | 월 1회 | 무제한 |
| 카테고리 자동 분류 | ✓ | ✓ |
| 해당 월 카테고리별 지출 요약 | ✓ | ✓ |
| 거래별 카테고리 수정 | ✓ | ✓ |
| 기간별 추이 | — | ✓ |
| 구독 누수 탐지 | — | ✓ |
| 이상거래 탐지 | — | ✓ |
| AI 월간 요약 | ✓ (Sonnet) | ✓ (Opus) |
| 절약 인사이트 · 이상거래 해석 | — | ✓ |

경계 원칙: **여러 달치 데이터가 쌓여야 의미가 생기는 기능은 전부 Pro.** Free 사용자도 계속 업로드하며 데이터를 쌓게 되고, 쌓일수록 Pro의 가치가 커진다.

Free는 **KST 캘린더 월 기준 업로드 1회**다. 한 파일에 여러 달이 들어 있어도 1회로 계산하므로, 여러 달치를 한 파일로 합쳐 올리는 편이 유리하다(행 수 상한 10,000). 매핑 추론이 실패한 업로드는 횟수를 소비하지 않고, 같은 출처의 동일 파일 재업로드도 기존 업로드·매핑을 재사용하며 횟수를 소비하지 않는다. 한도 도달 후에도 기존 데이터 열람·수동 수정·재분류는 계속 가능하다.

자동 분류는 두 플랜 모두 제공한다. 분류는 사용자 규칙 → 내장 가맹점 사전 → 남은 것만 Claude 순으로 처리하므로 상당 부분이 모델 호출 없이 끝난다. 분류는 미분류 거래가 소진되면 자연히 멈추고, AI 인사이트는 월 단위로 캐싱되므로 별도의 호출량 쿼터를 두지 않는다(ADR-012).

**지출의 의미:** 저장 금액은 절댓값이며 거래별로 지출·수입·환불·이체를 구분한다. 총지출과 카테고리 합계는 지출-환불이다. 급여, 본인 계좌 이체, 카드대금 납부는 총지출에 포함하지 않는다. 분류가 애매한 행은 사용자가 확인하며 저장 후에도 거래 유형을 수정할 수 있다.

## MVP 제외 사항
- 팀 / 다중 사용자 / 공유
- 은행 오픈뱅킹 API 자동 연동 (CSV 업로드만)
- 예산 설정, 목표, 푸시 알림
- 모바일 네이티브 앱
- 다국어 / 다통화 (KRW 고정)
- 데이터 자동 만료 정책 (사용자가 지울 때까지 보관)
- 사용자가 카테고리 자체를 추가/삭제하는 기능 (거래별 수정만 허용)
